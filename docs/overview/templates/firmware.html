Purpose and Scope

This page documents the boot infrastructure of BeanieOS, covering the OVMF UEFI firmware, the Liminar bootloader configuration (limine.conf) amd binary (BOOTX64.EFI), and the automated construction of the GPT-partitioned EFI System Partition (ESP) disk image via the product system.

1. UEFI Firware via OVMF

BeanieOS executes within QEMU using the Open Virtual Machine Firmware (OVMF) implementation of UEFI. The build and run targets configure QEMU with two distinct pflash (parallel flash) drives.

  • Code Flash (OVMF_CODE.4Mm.fd): Contains the read-only UEFI firmware executable code.
  • Variable Flash (OVMF_VARS.4m.fd): Contains non-volatie NVRAM storage for UEFI boot variables, NVRAM settings, and boot entries.

Limine Bootloader Configuration and Binary

Limine serves as the UEFI-compliant bootloader for BeanieOS. The bootloader binary is located at limine/BOOTX64.efi and is executed by the UEFI firmware once the ESP is loaded.


The bootloader behaviour is dictated by imine/limine.conf, which defines the execution timeout, boot protocol, and kernel path:

  • timeout: 0: Skips the boot menu selection screen and bots immediately.
  • protocol: multiboot2: Instructs limine to load the kernel using the Multiboot2 specification.
  • kernel_path: boot(2):/boot/kernel: Specifies that the kernel binary should be read from the second partition (boot(2)) at the path /boot/kernel

GPT/ESP Disk Image Layout and Build Process

The disk target in the project Makefileconstructs a bootable disk image (oout/beanieos.img) containing a GPT partition table and two FAT32 partitions: an EFI System Partition (ESP) and a BeanieOS partition.
