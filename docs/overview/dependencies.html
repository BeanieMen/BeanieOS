Dependecies and Crate Configuration

Purpose and Scope

This page details the crate configuration, dependency management, and build profiles for BeanieOS. Because BeanieOS operates as a freestanding (no_std) x86_64 hobby kernel, standard library abstractions like thread-local storage, heap allocators, and unwinding runtimes are unavailable. The build configuration defined in Cargo.toml and locked via Cargo.lock establishes a strict zero-host-dependency environment utilizing specialized no_std crates.

Profile Configuration and Panic Handling

In a bare-metal kernel evnvironment, panics cannot rely on platform-specific stack unwinding mechanisms (libunwind), because no operating system runtime exists to catch or clean up stack frames. To prevent the computer from nserting unwinding landing pads and depending on symbols like _Unwind_Resume, BeanieOS explicitly configures both development and release profiles to abort immediately upon panic.

Crate Ecosystem and no_std Dependecies

BeanieOS leverages a curated set of external crates compatible with freestanding execution. The dependency manifest configures these libraries with default features disabled where necessary to avoid reliance on the Rust Standard Library (std).

Core Dependency Breakdown

  • x86_64 (v0.15.5): Provides low-level abstactions for x86_64 architecture constructs, including page table management, Global Descriptor Table (GDT), Interrupt Descriptor Table (IDT), Control Registers, and port I/O operations.
  • multiboot2 (v0.28.0): Parses Multiboot2 boot information structures passed by the bootloader, enabling access to memory maps, framebuffer tags, and ACPI root pointers.
  • spin (v0.10): Supplies spinlock primitives (Mutex, Once) configured with default-features = false to operate in non-preemptive interrupt contexts where blocking mutexes cannot be used.
  • linked_list_allocator (v0.10): Implements a heap allocator over a raw memory region, acting as the global allocator via #[global_allocator].
  • pci_types (v0.10): Provides types and strructures for interacting with PCI devices, used for enumerating and configuring hardware. It disables default features to ensure no_std compatibility.
  • fatfs (v0.4.0): A FAT filesystem implementation, configured to use alloc without std for disk operations. This is sourced directly from Git repository.
