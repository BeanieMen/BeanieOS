Getting Started & Build System

Purpose & Scope

This page details the build infrastructure, toolchain requirements, and orchestration scipts for BeanieOS. It covers the Makefile compilation pipeline, the custom x86_64.json target specification required for bare-metal execution, code formatting settings in rustfmt.toml, and workspace exclusion rules in .gitignore.

1. Toolchain Requirements & Setup

BeanieOS targets a freestanding x86_64 environment, requiring a rust nigthly toolchain with standard library building support (-Zbuild-std), along with system utilities for disk image creation and virtualization.

The make setup target automates the installation of required Rust toolchain components and host utilities (assuming an Arch Linux environment using yay):

  • Installs the default stable and nigthly Rust toolchains.
  • Adds the llvm-tools-preview component to the nightly toolchain for post-processing binaries
  • Installs QEMU system emulators, partition managers (parted), and FAT filesystem tools (dosfstools, mtools).

2. Makefile Targets & Build Pipeline

The Makefile coordinates the transition from raw assembly and Rust source files to a bootable UEFI disk image running inside QEMU.

Build Pipeline Architecture

Key Makefile Target

  • make boot: Assembles the initial bootstrap code from src/srch/boot.s using the GNU assembler into target/boot.o
  • make kernel: Compiles the Rust kernel using the nightly compiler, passing -Zbuild-std=core,alloc and -Zjson-target-spec with x86_64.json. It links against target/boot.o and linker.ld, then strips debug symbols using llvm-strip.
  • make disk: Generates 128MB raw disk image (out/beanieos.img) creates a GPT layout with a FAT2 EFI System Partition (ESP), and copies the Limine bootloader (BOOTX64.EFI), the stripped kernel binary, and limine.conf into the appropriate EFI directory structures.
  • make run: Boots the generated disk image in QEMU configured with UEFI OVMF firmware (OVMF_CODE.4m.fd and OVMF_VARS.4m.fd) and SDL display.
  • make link / make clippy: Runs code format verfication (fmt-check) and static analysis via Clippy with strict warning checks (-D warnings).

3. Custom Target Specification (x86_64.json)

Because BeanieOS runs on bare metal without an underlying operating system, standard compliation targets are insufficient. The custom target specification file x86_64.json defines the target architecture parameters for LLVM and cargo.

Target Configuration Breakdown

  • llvm-target: Set to x86_64-unknown-none, informing LLVM that there is no OS abstraction layer.
  • panic-strategy: Configured to abort since there is no unwinding runtime available in a freestanding kernel.
  • disable-redzone: Set to true to prevent the x86_64 ABI red zone (128 bytes below the stack pointer) from being modified by interrupt handlers, which would corrupt asynchronous stack frames.
  • features: Explicitly disables MMX and SSE instructions (-mmx, -sse) and enforces software floating point (+soft-float), preventing the CPU from using vector registers before they are properly initialized by the kernel.
  • linker: Uses rust-lld with the ld.lld linker flavor.

4. Code Style & Repository Hygiene

BeanieOS maintains strict formatting rules and excludes build artifacts via configuration files at the repository root.

Formatting (rustfmt.toml)

The rustfmt.toml configuration file enforces code style rules across all source files:

  • editon: Set to "2024" [rustfmt.toml:1-1()].
  • max-width: Capped at 100 characters per line [rustfmt.toml:2-2()].
  • use_small_heuristics: Set to "Default [rustfmt.toml:3-3()].

Version Control Exclusion (.gitignore)

The .gitignore file prevents local build artifacts, editor configurations, and auxiliary directories from being commited to version control:

  • Excludes /target, out/ and ,vscode/ or .opencode/ editor directories.
  • Excludes documentation (docs/), blog posts (blog/), and utility scripts (scripts/).
