Development Journal

Purpose and Scope

This page summarizes the evolutionary milestones, technical hudles, and design decisions recorded in the project's development journal (JOURNAL.md). It traces the trajectory of BeanieOS from initial concept and legacy VGA restrictions to a modern x86_64 bare-metal kernel featuring a graphic framebuffer, CPU exception handling, interrupt controllers, and automated build tooling.

1. Framebuffer Transition and Graphics Output

Early milestones focused on abandoning the legacy 80x25 VGA text mode in favour of a modern graphics framebuffer. This ransition required inegrating bootloader protocols (Multiboot2/Limine) to pass framebuffer metadata (resolution, pitch, and pixel format) directly to the kernel initialization routines.

2. CPU Architecture and Interrupt Management

Configuring x86_64 CPU protection structures proved to be a major architectural hurdle, specifically coordinating the Global Descriptor Table (GDT), Task State Segment (TSS), Interrupt Descriptor Table (IDT), and Interrupt Stack Table (IST).

3. Paging and Memory Mapping

Paging was initially enabled by bootloader wrapper. Kernel iniialization extracts boot information structures (bootinfo), obtains the physical memory offset, and computes virtual addresses for page tables anchored by the control register.

4. Developer Workflows and Tooling

To streamline cross-compilationan and testing workflows (especially after shifting environments to CachyOS),the project introduced automated build scripts and dependency targets within the root Makefile.

5. Freestanding Memory Routines

As a no_std kernel, standard library memory manipulation functions like memset, memcpy, memmove, and memcmp are not available. These essential routines, required for various kernel operations, are implemented manually in src/mem.rs to provide C-ABI compatible memory instrinsics.
